# 公開前チェックリスト

このファイルは `japanese-tech-writing` スキルの点検リストであり、`SKILL.md` から読み込まれる。
公開前チェック（モードC）で使う。
推敲モード（モードB）でも、各パスの仕上げ確認として参照してよい。

各見出しは [rules.md](rules.md) の見出しと対応する。
違反の判断根拠や具体例は rules.md 側に譲り、ここでは点検項目とその severity だけを列挙する。

## severity の3段階

数値採点や合格ラインは使わない。違反ごとに次の3段階のどれかを割り当てる。

- **BLOCKER**：論証や読者の信頼を破壊する違反。未解消の自己矛盾、根拠のない断定を事実として述べる、機構を欠いた因果主張などが該当する。公開前にすべて解消する。
- **IMPORTANT**：明確な品質問題。LLM っぽい空虚な言い回し、冗長な段落、オチを割る見出しなどが該当する。原則としてすべて直す。締め切りの都合で残す場合は、残した箇所と理由を明記する。
- **TASTE**：文体上の微調整。リズムやダッシュ運用の際どい判断などが該当する。著者の裁量で残してよい。

同じ規範でも、明白な違反と際どい判断とで severity が変わることがある。
項目ごとに書き分けている。

## 1. 整形

- [ ] **[BLOCKER]** 本文が、自らすでに述べた規範や定義に違反していないか（自己矛盾）。典型例は、「中黒を並列で使わない」と述べた直後の地の文で中黒を並列使用する、ダッシュ運用を説明する文自体がダッシュ規範に違反する、といったケースである。規範文書に限らず、用語の定義や方針を宣言した文書全般で点検する。
- [ ] **[IMPORTANT]** 一文ごとに改行し、段落を空行で区切っているか。
- [ ] **[IMPORTANT]** コード、差分、ログ、設定ファイルの断片がコードブロックに収まっているか。
- [ ] **[IMPORTANT]** 本筋から一段外れる補足（用語の由来、定式化の名称など）を本文に並べず脚注に降ろしているか。
- [ ] **[IMPORTANT]** 定義や分類の列挙を箇条書きにし、定義される用語を太字にしているか。
- [ ] **[IMPORTANT]** 用語を初めて定義または導入する箇所は太字、以後その語を話題として指す箇所は「」になっているか（太字と「」を混同していないか）。
- [ ] **[IMPORTANT]** em ダッシュ、horizontal bar、二倍ダッシュを日本語の地の文や見出しで使っていないか。同格や補足の挿入を括弧に、言い換えや敷衍を句点区切りや読点でつなぐ形に置き換えられているか。
- [ ] **[TASTE]** 範囲を示す en ダッシュや `Curry–Howard` のような英語の複合語、コードブロックや書誌情報中のダッシュを、誤って規範違反として扱っていないか（対象外の判断が際どいケース）。
- [ ] **[IMPORTANT]** 中黒（・）を日本語の並列で使っていないか。
- [ ] **[TASTE]** 単一の固有名詞内部での中黒使用を、誤って規範違反として扱っていないか（対象内かどうかの判断が際どいケース）。
- [ ] **[IMPORTANT]** 見出しやコラム見出しが、区切り線やダッシュ類で「種別──主題」のように二要素を詰め込んでいないか。単一の自然な句になっているか。コラム見出しが「基礎」「補足」のような種別名だけで済んでいないか。
- [ ] **[IMPORTANT]** 用語とその定義を並べる箇条書きが、区切り線ではなく全角コロンで「**用語**：説明」の形になっているか。

## 2. 段落と論証の構成

- [ ] **[IMPORTANT]** 一つの段落に一つのトピックだけが置かれているか。場面の進行が複数混ざった長い段落を分割できていないか。
- [ ] **[IMPORTANT]** 段落の最初の文を読めば、その段落が何の話かわかるか。
- [ ] **[IMPORTANT]** 段落の先頭で、前の段落との論理関係を接続表現で明示しているか。
- [ ] **[IMPORTANT]** 論証が一方向に進んでいるか。結論を出してから反論を処理し、また結論を言い直す構成になっていないか（反論と疑念の処理を終えてから結論を一度だけ置いているか）。
- [ ] **[IMPORTANT]** 例への弁明（作為的に見えることへの先回りなど）を、場面の山場の直後に挟んで流れを切っていないか。次の節の冒頭にまとめられているか。
- [ ] **[IMPORTANT]** 読者が立てそうな誤った解釈を、明示的に否定してから本当の理由を述べているか。
- [ ] **[BLOCKER]** 「AではなくB」と否定する文に、否定の根拠となる一文が添えられているか。根拠のない「AではなくB」を事実であるかのように置いていないか。
- [ ] **[BLOCKER]** 譲歩（「確かに〜」）が事実の確認にとどまっているか。あとで訂正する内容を著者の声で因果として断定し、自己矛盾になっていないか。表面的な診断を認める場合、読者や通説の声に帰属させているか。
- [ ] **[IMPORTANT]** 山場で効かせたい情報（数値、固有の事実）を、その手前の段落で先出ししていないか。
- [ ] **[IMPORTANT]** 何かを否定する、あるいは限定する文で、否定する命題そのものを「」で正確に書き出しているか。「何もかもが解決するわけではない」のような漠然とした否定で済ませていないか。
- [ ] **[IMPORTANT]** 「後の章で扱う」のような前方参照を、論証が一段落した段落末や節末に置いているか。論証の途中に挟んで流れを切っていないか。

## 3. 論証の厳密さ

- [ ] **[BLOCKER]** 推量、可能性、読者の疑念、反実仮想として書かれている文を、根拠なく断定に変えていないか。「かもしれない」「だろう」などを削るのは、本文内の根拠で命題が確定している場合に限られているか。
- [ ] **[BLOCKER]** 区別すべき異なる対象（別々の決定、別々の原因、種類の違う問題）を、一括りの言葉でまとめていないか。
- [ ] **[BLOCKER]** 複数の要因がある事象を単一の原因に還元していないか。複数種類の問題が混ざる例で、それぞれを切り分け、どの道具がどれを説明するのか対応づけているか。
- [ ] **[BLOCKER]** 同じ概念の扱いが章や節をまたいで一致しているか。ある節での分類、定義、用語の地位が、別の節と食い違っていないか。
- [ ] **[BLOCKER]** 因果を主張する文に、その機構（なぜそうなるのか）が一文で示されているか。「AだとBになる」とだけ書いて理由を省略していないか。
- [ ] **[BLOCKER]** 検出、保証、解決を「必ず」できるかのように書いていないか。条件付きで正確に述べているか（「〜しやすい」「〜が成り立つときに限り」など）。
- [ ] **[BLOCKER]** 挙げた例が、主張の全体を実際に支えているか。例が一部しか支えない主張を、範囲を狭めずそのまま置いていないか。
- [ ] **[BLOCKER]** 「次節で扱う」と前方に逃がした論点が、実際にそこで回収されているか。回収されない伏線が残っていないか。
- [ ] **[BLOCKER]** 譲歩や限定（「ただし」「とはいえ」）を置いた後、必ず論を進めているか。逆接で終えて宙吊りにしていないか。
- [ ] **[IMPORTANT]** 節の中心となる語を、その節以前に定義と対象範囲を述べてから使っているか。定義せずに使い始めていないか。
- [ ] **[BLOCKER]** 複数の概念を一つの上位語にまとめる箇所で、命名の直前にそれらが同じものに帰着すると一文で述べているか。

## 4. 読み手の負荷の管理

- [ ] **[IMPORTANT]** 後で参照する必要のない固有名（ファイル名、関数名、識別子）を、一般的な言い方に置き換えられずそのまま出していないか。
- [ ] **[IMPORTANT]** 文脈から一意に決まらない抽象的な言い回しに、丸括弧による同格挿入でその場の特定を添えているか。
- [ ] **[IMPORTANT]** 新しい例や場面を追加する箇所で、前の例と何が違うのか、なぜもう一つ必要なのかを前置きしているか。
- [ ] **[IMPORTANT]** 章冒頭や節の導入に、これから扱う内容に関係しない過剰な詳細を詰め込んでいないか。
- [ ] **[IMPORTANT]** 例の節で、その節の問いや帰結に関係しない過剰な詳細（装飾的精度としての時刻、HTTP ステータス、カバレッジ率、後で参照しない固有名など）だけを削り、議論に必要な具体は残しているか。

## 5. 視点と語り

- [ ] **[IMPORTANT]** 例示が、結果の羅列や受動態ではなく、行為者を主語にした動作の連なりで書かれているか。
- [ ] **[IMPORTANT]** 「入社2年目のエンジニアが」のような架空の人物設定を、無意味に冠していないか。
- [ ] **[IMPORTANT]** 論証の中で読者を「あなた」と呼んでいないか。二人称の呼びかけが、場面への導入や、章や本の結びなど限られた要所にとどまっているか。
- [ ] **[IMPORTANT]** 対象を指す語を具体的に選んでいるか。「AI」「ツール」のような広い語でぼかしていないか。
- [ ] **[IMPORTANT]** 章や節で定式化や術語を導入した後、その語で通しているか。「文脈」「ツール」のような曖昧語に後退していないか（定式化前の導入語としての使用は対象外）。
- [ ] **[IMPORTANT]** 術語や訳語に、その分野で慣用されている語を選んでいるか。意味の近い漢語を一般語の感覚で充てていないか。
- [ ] **[TASTE]** 人物への言及が原綴りになっているか。歴史上の人物や人名を冠した概念を定着名で紹介する箇所で、日本語で通用しているカタカナの通称を使う判断は妥当か。
- [ ] **[IMPORTANT]** 術語の響きを持つ語を、術語でない場面に流用していないか（システムから人間までの連なりを「経路」と呼ぶ、など）。

## 6. 演出の抑制

- [ ] **[IMPORTANT]** 溜めや修辞疑問による演出が、緊張が議論に効く要所に限られているか。説明で足りる箇所をそのまま述べているか。
- [ ] **[IMPORTANT]** 短い決め台詞を独立した段落にする演出を多用していないか。段落内の短い体言止めが、場面の山場に限られているか。
- [ ] **[IMPORTANT]** 本文中の太字強調が、誤読を防ぐ否定や節の帰結など論理の要所に限られ、一節に一、二箇所までに収まっているか。
- [ ] **[TASTE]** 「〜してはならない」という命令調の断定より、「〜するわけにはいかない」のような作業者の判断として書く形を選べているか。
- [ ] **[IMPORTANT]** 転回点を過剰に劇的にしていないか。事実を述べる一文で足りる箇所を、感嘆符つきの演出で膨らませていないか。
- [ ] **[IMPORTANT]** 帰結の列挙によって事故や危険を煽っていないか。
- [ ] **[IMPORTANT]** 「重要なのは〜である」のような前置きで主張を予告せず、主張をそのまま書いているか（主張の様式を宣言する前置きは対象外）。
- [ ] **[TASTE]** 「AではなくBだった」という対句の決め台詞を多用していないか。軽い補足や評価を括弧書きで添えられているか。
- [ ] **[IMPORTANT]** 慣用表現をひねった言い回しや、指す内容が一意に決まらない比喩を使っていないか。平易な動詞でそのまま言えているか。

## 7. LLM っぽい表現の禁止

rules.md 側の該当節にある語彙は、論証や構成に絡む言い回しの抜粋である。
AI 臭語彙全般の検出は `naturalize-ja` スキル（`references/ai-japanese-patterns.md` が正本）に委譲する。
ここでは rules.md に挙げられたカテゴリだけを点検する。

- [ ] **[IMPORTANT]** 予告と総括（「重要なのは〜である」「本章では〜を扱う」「まとめると」「〜に他ならない」など）を使っていないか。
- [ ] **[IMPORTANT]** 「正面から扱う／回収する／見る」のような、中身の代わりに姿勢だけを宣言する言い回しを使っていないか。
- [ ] **[IMPORTANT]** 「不可欠」「核心的」「鍵となる」「多角的」「包括的」のような、中身を説明せず強調や網羅感だけを付ける形容を使っていないか。
- [ ] **[IMPORTANT]** 「掘り下げる」「深掘りする」「言語化する」「触れる」「言及する」のような、何をどう書いたか示さず終わる動詞を使っていないか。
- [ ] **[IMPORTANT]** 「〜において」「〜という側面から」のような新情報のない接続の型や、「さらに」「また」「加えて」の連打を使っていないか。
- [ ] **[IMPORTANT]** 根拠なく主張を弱める「〜と言えるだろう」「〜かもしれない」や、中身のない「非常に」「極めて」のような強調語を使っていないか（推量、仮定、読者の疑念、作中人物の認識を表す場合は対象外）。

## 8. 冗長の排除

- [ ] **[IMPORTANT]** 同じ主張を言い換えて繰り返していないか。一つの主張が一度だけ書かれているか。
- [ ] **[IMPORTANT]** 隣接する節が同じことを別の角度で述べ、役割が重複していないか。重複があれば一つの節に吸収できているか。
- [ ] **[IMPORTANT]** 場面を描写した直後に、その内容を要約し直していないか。意味づけの一文だけを置けているか。
- [ ] **[IMPORTANT]** 同じ論理的役割を持つ並列の事実を、文を分けて重ねず一文にまとめ、論理的地位を文頭の語で示しているか。
- [ ] **[IMPORTANT]** 読者が自力で補える中間段階の説明を書いていないか。
- [ ] **[IMPORTANT]** 数文にわたる議論を一文に圧縮できる箇所で、圧縮した一文だけを残しているか。
- [ ] **[IMPORTANT]** 接続や評価のためだけの文（「それ自体はよいことである」など）を置いていないか。
- [ ] **[IMPORTANT]** 想像上の読者との問答や、読者の反応を演じて応答する形を修辞として使っていないか。譲歩を地の文で簡潔に行えているか。
- [ ] **[IMPORTANT]** 読者が抱きそうな発想を、「ここまでの話には自然な続きがある」のようなメタな枠取りで紹介せず、その発想自体を直接書いているか。
- [ ] **[IMPORTANT]** 「本書もそれを否定しない」のような著者の立場の弁明や断りを書かず、事実の記述だけを置いているか。
- [ ] **[IMPORTANT]** 文脈を最短で読み手と共有できているか。導出を一歩ずつ展開しなくても伝わる箇所で、構造に名前を与えて言い切れているか。
- [ ] **[IMPORTANT]** 本文でまだ導入していない概念や文書名を、先回りして持ち出していないか。
- [ ] **[IMPORTANT]** ためらいのある弱い述語で済ませず、本文内の根拠で確定していることを強く具体的に言い切っているか（不確実性、可能性、仮定、読者の疑念を表す弱い述語は対象外）。
- [ ] **[TASTE]** 文章のリズムを作るための接続表現（「しかし一方で」など）を、誤って冗長と判定していないか。

## 9. 見出しの付け方

- [ ] **[IMPORTANT]** 見出しが、作業の手順だけを述べる形（「例に戻す」など）や情報量のない形になっていないか。その節が答える問い、または扱う対象を指しているか。
- [ ] **[IMPORTANT]** 見出しが、節の結論を言い切る「セリフ」になっていないか。見出しの時点で読者がオチを知る状態になっていないか。
- [ ] **[TASTE]** 疑問形か対象を指す名詞句かの選択が、本文のトーンに合っているか。

## 10. 読者への誠実さ

- [ ] **[IMPORTANT]** 例が作為的に見えうる場合、それを隠さず、読者の疑念を先回りして認めているか。
- [ ] **[BLOCKER]** その根拠が、著者の断定（「十分あり得る状況だ」）ではなく、読者自身の経験に訴える一般的事実や通説（「この症状は珍しくないだろう」など）に求められているか。著者の断定を裏づけなしの事実として置いていないか。
- [ ] **[BLOCKER]** 確認していないことを、確認したかのように滑らかに書いていないか。

## 総合判定

数値による合否判定は行わない。severity の集計だけで判定する。

- BLOCKER が一件でもあれば、公開前に対応が必要である。該当箇所をすべて解消してから次に進む。
- BLOCKER がなく IMPORTANT が残っている場合、公開は可能だが改善の余地がある。締め切りの都合で残す場合は、残した項目と理由を明記する。
- IMPORTANT もなく TASTE のみ、または違反がない場合、公開可とする。TASTE は著者の裁量で残してよい。
